# Beta 范围、验收与恢复

本页记录候选版本的验收要求。构建成功、单测通过和历史功耗数据不能单独证明整机运行安全；仓库里的改动也不等于已经向用户发布。

## 建议的邀请测试范围

先邀请能提供反馈的技术用户，明确记录其 Mac 型号、macOS 版本、Agent 版本、安装来源及使用模式。当前工具链本地验证主要来自 Apple Silicon；Intel 通用二进制可构建，不代表 Intel 和 macOS 13 的实机体验已验收。

建议先验证后台手动会话、命令包裹、目录跟随和 Claude Hook。合盖标准与兼容模式均为实验性功能，只有具体机器完成恢复测试后才纳入该机器的测试范围。若某次 beta 不包含合盖，应在候选中禁用相关入口，不能只依赖免责声明。

GUI 桌面操控需要已解锁的会话。屏幕常亮不会绕过系统锁屏或安全策略。低电量、拔电、温控截止适用于菜单栏应用管理的会话；独立 CLI 包裹按进程生命周期运行，不会自动终止工作负载。

## 各信号的边界

| 方式 | 持有 / 释放依据 | 使用限制 |
| --- | --- | --- |
| 手动会话 | 用户启动、停止或设定到期 | 无限时会话需用户自行停止 |
| 目录自动跟随 | 文件创建或写入；30 秒活动窗口 + 5 分钟宽限期 | 文件变化不等于任务状态；单轮上限 2 小时；长时间无写入可能提前释放 |
| 显式 Hook | 各 Agent、各 session 的开始和停止事件 | 事件需要正确配对；应实际验证安装路径和事件抵达；仍有自动会话安全上限 |
| CLI 包裹 | 被包裹的直接子进程退出 | 直接子进程退出不保证所有派生后台任务也已结束；终端程序的交互与信号需要验证 |
| CLI watch | 指定 PID 退出或取消跟随 | 取消保护不会终止被跟随的进程；PID 不代表工作进度 |

目录跟随开关只控制目录监听；已连接的显式 Hook 有独立的连接 / 断开操作。手动停止当前忙碌的跟随会话后，该轮静默才重新待命；在目录原本安静时停止手动会话，不应漏掉下一轮任务。

`sleepskip status` 读取正在运行的菜单栏应用快照，不是所有系统断言的总表。独立 CLI 可以在菜单栏应用未运行时工作；系统断言可通过 `sleepskip doctor` 按需查看。

## 候选验收表

每个测试候选都应附带版本、构建号、源码基线或哈希和对应日志。勾选项必须指向实际执行结果。

- [ ] 完整 Swift 单测、`scripts/verify.sh`。
- [ ] `bash scripts/verify_release.sh`，beta 标签标记为预发行且不更新稳定 tap。
- [ ] `SLEEPSKIP_BINARY=/absolute/path/to/SleepSkip python3 scripts/verify_cli.py`：实际终端输入、退出状态、中断、watch 取消与进程清理。
- [ ] `bash scripts/probe_app_integration.sh`：临时目录中的真实文件事件、路径别名、来源变化和模拟系统守护。
- [ ] 单轮上限、跨轮短任务、手动停止后重新待命、两个来源并发与逐个结束。
- [ ] 长 / 分段 Hook 输入、多个 session、缺失或无效输入、真实 Agent 开始和停止。
- [ ] 真实授权取消、120 秒超时、迟到成功、退出及恢复；先完成模拟验证，再安排不影响其他任务的真机测试。
- [ ] 选定安装渠道的干净安装、CLI / Hook 实际可执行、开机启动、升级、卸载与反馈流程。
- [ ] 开启和拒绝通知两种情况，用户仍能理解为什么停止。
- [ ] 分别测量待机、目录跟随、Hook 和标准合盖；20 秒待机门禁只覆盖待机状态。

真实合盖还需分别验证电池、稳定插电、拔电、合盖后重新插电、锁屏、到期、强退和异常退出恢复。标准模式在合盖后重新插回电源时仍有已观察到的 6–9 秒后睡眠限制。温控截止只释放防休眠，不会停止高负载任务，也不保证降温；保持通风，不宣传可以放心放进背包。

## 安装与更新渠道

邀请 beta 可在明确知情的技术用户中使用 Ad-hoc 包；必须提前解释 Gatekeeper 行为。开发者签名和 Apple 公证尚需实际凭证与首次下载验收，签名完整性检查不能替代它们。

打包使用 `VERSION=1.6.0-beta.1 BUILD_NUMBER=123 ./scripts/build_app.sh`。完整标签保留在文件名和应用版本展示中，系统营销版本为 `1.6.0`，构建号独立为正整数。发行工作流以其递增运行号提供构建号；本地构建可显式指定，避免混用不同编号来源。beta 标记为 GitHub prerelease，稳定 Homebrew tap 只接受稳定版本。

## 出现意外防休眠时

1. 打开面板查看持有来源和最近记录；在终端运行 `sleepskip status --json`、`sleepskip doctor`，记录版本、时间、模式和复现步骤。
2. 停止菜单栏会话；CLI watch 可取消，包裹命令可按正常终端操作中断。取消 watch 只释放保护，不终止目标任务。
3. 兼容合盖停止后若仍看到 `SleepDisabled = 1`，先确认没有其他工具或管理员策略在使用它，再在面板选择恢复正常睡眠。必要时由用户执行 `sudo pmset -a disablesleep 0`。此操作会修改系统配置，应先确认自己的任务不再需要它。
4. 卸载前断开 Claude Hook（设置中的断开，或 `sleepskip hook uninstall`），关闭开机启动，停止会话并退出应用，再卸载所选安装渠道的程序。

反馈时使用仓库问题模板，附上上述诊断和操作顺序即可；不要提交会话正文、令牌或凭证。诊断输出可能包含命令名和路径，分享前先自行检查。
